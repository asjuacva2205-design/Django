Mini 7 · useStateContador completo

Archivo: Frontend/src/features/misiones/dia2/Contador.jsx. Los tres botones comparten el mismo estado cuenta. Lo único nuevo frente al punto de partida son dos funciones y dos botones; los atributos data-cuenta y data-aumentar permanecen intactos. 

import { useState } from 'react'

export default function Contador() {
  const [cuenta, setCuenta] = useState(0)

  function aumentar() {
    setCuenta(cuenta + 1)
  }

  function disminuir() {
    setCuenta(cuenta - 1)
  }

  function reiniciar() {
    setCuenta(0)
  }

  return (
    <div>
      <output data-cuenta>{cuenta}</output>
      <button type="button" data-aumentar onClick={aumentar}>
        Colocar pieza
      </button>
      <button type="button" onClick={disminuir}>
        Quitar pieza
      </button>
      <button type="button" onClick={reiniciar}>
        Reiniciar
      </button>
    </div>
  )
}
Reto extra — no bajar de 0 
function disminuir() {
  if (cuenta > 0) {
    setCuenta(cuenta - 1)
  }
}
Respuesta esperada en la frase de entrega Una idea equivalente a: el número en pantalla vive en el estado de React; setCuenta avisa a React que el estado cambió y obliga a redibujar el componente. Asignar cuenta = cuenta + 1 solo cambia la variable en memoria, React no se entera y la pantalla queda igual. Aceptá cualquier redacción propia que tenga esas dos partes (el estado no cambia / la pantalla no se actualiza).

Minis 8 y 10 · fetch y mapMás datos en la lista

Archivo: Frontend/src/features/misiones/dia2/Listado.jsx. El fetch y el useEffect no se tocan: todo el cambio está en lo que imprime cada <li>. Los nombres van con guion bajo porque así llegan del JSON: entidad_compradora y valor_total. 

return (
  <ul>
    {contratos.map((contrato) => (
      <li key={contrato.id_contrato} data-id-contrato={contrato.id_contrato}>
        {contrato.id_contrato} — {contrato.entidad_compradora}{' '}
        — valor ${Number(contrato.valor_total).toLocaleString('es-CO')}
      </li>
    ))}
  </ul>
)

El formato con toLocaleString es optativo; se acepta también el número tal cual llega (1234567.00). Si un aprendiz lo dejó plano, está bien: el criterio es que los tres datos se vean.

Reto extra — departamento Se agregó en el modelo del Día 1, así que en su JSON aparece departamento. La línea extra: 
— {contrato.departamento}
Respuesta esperada en la frase de entrega Una idea equivalente a: la key es la etiqueta con que React identifica cada elemento de la lista; le sirve para saber cuál cambió, cuál se agregó o cuál desapareció y actualizar solo eso en lugar de redibujar toda la lista. Se acepta también la versión de estabilidad (evita errores de estado compartido entre items reordenados).

Mini 9 · CORSRompan CORS a propósito

Estado roto (lo que debe verse en su captura)

  • En settings.py, la lista queda con un solo origen — por ejemplo solo http://127.0.0.1:5173.
  • Console (o Network) muestra el bloqueo: el mensaje típico es No 'Access-Control-Allow-Origin' header is present on the requested resource o el atajo CORS error en la columna Status de Network.
  • Dato fino que distingue a quien leyó de verdad: en Network la petición aparece en rojo y su status puede verse como blocked:CORS o simplemente fallida — Django sí respondió (200 en el servidor), pero sin el encabezado el navegador lo tapa. Si en la captura aparece un 500 o un error de conexión, rompieron otra cosa y hay que revisar juntos.

Estado reparado

El origen vuelve a la lista: 

CORS_ALLOWED_ORIGINS = [
    'http://localhost:5173',
    'http://127.0.0.1:5173',
]

Guardado + reinicio de runserver + lista mostrando contratos otra vez. El reinicio es criterio de aprobación: sin él, la reparación no se demuestra.

Reto extra — puerto 5174 Falla porque el origen se define por protocolo + dominio + puerto: 5174 es un origen distinto de 5173. Con esa línea, React corre en un origen no autorizado y el navegador vuelve a bloquear la respuesta.
Respuesta esperada en la explicación de 3-4 líneas Debe cubrir las tres preguntas. Referencias de comparación:
  • Origen: la combinación de protocolo + dominio + puerto (http://localhost:5173 es un origen; http://localhost:8000 es otro).
  • Quién bloquea: el navegador. Django respondió, sin encabezado CORS el navegador recibe la respuesta y decide no dársela a la página.
  • CORS_ALLOWED_ORIGINS: es la lista de orígenes externos a los que Django sí les envía el encabezado Access-Control-Allow-Origin — la lista de visitantes con permiso pagado del Portero.
Se aceptan todas las redacciones propias; lo que no se pasa es una explicación que diga que "Django arroja el error", porque invierte a los responsables.
